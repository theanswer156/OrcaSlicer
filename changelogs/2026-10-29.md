## 重要合并

### 1. 新增 PrintaLot PLA 耗材配置（Bambu Lab 打印机）
- **PR**：#16951（`f082706`）
- **说明**：为 Bambu Lab A1 / A1M / A2L / H2C / H2D 系列打印机新增 PrintaLot PLA 耗材配置文件，覆盖 0.2mm 与 0.4mm 喷嘴。同步更新 `OrcaFilamentLibrary.json` 耗材库索引。
- **影响范围**：`resources/profiles/Printalot/BBL/` 下新增 12 个配置文件，耗材库 +110 行。

### 2. PA Line 校准测试改用所分配耗材的设置
- **PR**：#16882（`4b68224`）
- **说明**：此前 PA Line 校准测试无论分配到哪个耗材，均从耗材 0 读取速度上限、线宽和挤出量。在非 AMS 0 号槽或其他耗材上测试时，打印速度和挤出量均错误。现改为使用 G-code 生成器为该测试选定的耗材：快速线段受该耗材最大体积速度限制，线宽取该耗材挤出机的喷嘴直径，挤出量按 `Extruder::e_per_mm() × print_flow_ratio` 计算（与常规打印一致）。
- **测试**：新增回归测试验证分配到两种不同耗材中第二种时的 PA 线进给率和挤出量。

### 3. 细分网格后保留锐边上的涂漆
- **PR**：#16484（`d709eb2`）
- **说明**：开启"网格变更后保留涂漆特征"时，细分网格操作现可保留锐边和角上的涂漆。涂漆数据在顶点平滑前先重新映射到细分后的网格上；因细分网格仍位于旧表面、且平滑后网格三角形不变，涂漆数据保持有效。菜单项不再显示"(Lost color)"。

## 稳定性与可靠性

### 4. 切片崩溃：带 raft 时物体过薄无任何层
- **PR**：#17013（`59f0cc3`）
- **说明**：使用 raft 时，过薄到无法生成任何层的物体会得到空层列表，但 `groupingVolumesForBrim()` 读取首层、`adjust_layer_series_to_align_object_height()`（Precise Z height 开启时）读取末层均未判空，前者在 `slice()` 自身判空前调用，后者在 `Print::validate()` 中运行导致切片开始前即崩溃。两处现均对空列表提前返回，使切片正常到达已有的"No layers were detected"错误。
- **关联**：修复 #17009。

### 5. 崩溃：向无脚本的预设转移后处理脚本
- **PR**：#16963（`98619b6`）
- **说明**：将未保存的后处理脚本转移到无脚本的预设时，`apply_only` 对空目标列表调用 `set_at()`，而 `set_at()` 读取列表首值导致崩溃。现对空目标列表先赋首值，空源列表则替换目标列表。同时 `deep_diff` 将序列化列表（后处理脚本、流量补偿模型）作为整体设置上报，未保存更改与比较预设对话框的展示与设置页一致。

### 6. 崩溃：打开 Design 标签后新建项目
- **PR**：#16997（`0db3244`，合并 `ba75670`）
- **说明**：若会话中曾打开 Design 标签且此时 OrcaSlicer 非活动窗口，新建或打开项目可能崩溃。现已修复，Design 标签仍会如前为新项目清空。仅在 CAD 功能开启时可达，不影响切片或项目文件。

### 7. 崩溃：枚举列表选项缺少 keys map
- **PR**：#16966（`d28c71c`）
- **说明**：静态打印配置默认值中的枚举列表选项未设置 keys map。从中拷贝的配置（如 `DynamicPrintConfig::full_print_config()`）将这些选项写为空字符串，读取名称时崩溃。`StaticCache::finalize()` 现通过 `create_default_option()` 设置 `coEnums` 默认值，补齐 keys map。选项值不变。
- **关联**：修复 #16964。

### 8. Moonraker 打印机将 3MF zip 当作 G-code 上传
- **PR**：#16968（`187baae`）
- **说明**：开启"使用打印机代理"时，Moonraker 打印机的"打印底板"和"发送"将底板的 `.gcode.3mf` 包以 `.gcode` 名称上传，Klipper 把 zip 当 G-code 读取并取消打印。现改为从包中提取 G-code 以作业名上传；配置了 `use_3mf` 的打印机仍上传 `.gcode.3mf` 包。Qidi 代理的打印启动按 plateindex 命名底板，文件名加引号以保留空格、撇号和非 ASCII 字符。
- **关联**：修复 #16954，承接 #16453。

### 9. Publish 3MF 耗材变体导出/导入错误
- **PR**：#16984（`c0efd44`）、#17014（`45a29d3`）
- **说明**：带变体的耗材键按 (槽位, 变体) 存值，但发布路径按槽位寻址——导出在较早耗材有多个变体后保留错误列，导入将所有材料键写入接收方变体 0，Full Publish 仅复制单个变体。新增列模型（`PublishSettings`）基于 `filament_self_index` 与精确变体匹配，导出按列而非槽位掩码、丢弃外列键，导入按列回填。Full Publish 拷贝变体键时仅在文件含全部作者列时复制，否则丢弃长度不符的变体键。

### 10. 打印机代理固件检查误阻塞空闲打印机
- **PR**：#16970（`d81a212`）
- **说明**：`MachineObject::upgrade_display_state` 改为枚举时丢失初始化，仅 Bambu 状态消息赋值。Moonraker/Qidi 打印机保留内存中的任意值，导致打印和发送对话框可能将空闲打印机误判为"正在升级固件"而阻塞。现已初始化为 `UpgradingUnavaliable`。发送对话框改用 `get_shown_printer_name()` 标记打印机（显示"名称 (IP)"），同名打印机各自独立条目。

## 需要关注

1. **Moonraker G-code 上传修复**（#16968）：改动量较大（+415 行，含 245 行测试），同时触及 Moonraker 与 Qidi 代理的上传路径和打印启动命令。建议在真实 Moonraker/Klipper 打印机上验证：常规 G-code 上传、`use_3mf` 配置的 3MF 包上传、含空格/非 ASCII 字符的作业名。

2. **Publish 3MF 变体修复**（#16984、#17014）：引入了全新的列模型处理 `filament_options_with_variant`，涉及导出、导入、Full Publish 三条路径。变体列错位曾导致一个变体静默读取另一个变体的值，属于数据正确性问题。建议对多变体耗材的 3MF 发布/导入做端到端回归测试，尤其关注 AMS 多槽位场景。

3. **wxWidgets 依赖升级**（#17015）：跨平台 GUI 基础库升级，虽然仅指向含 Wayland seat release 修复的 fork 提交，但 wxWidgets 变更可能影响 Linux/Wayland 以外的平台行为。建议关注 CI 全平台构建及 GUI 交互回归。
